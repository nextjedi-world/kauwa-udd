# Kauwa Udd

Party game ("last bird wins the sky"): hold, release, react. Players join a room by code, each round
shows an object, and you release (or not) depending on whether it flies. Live at
https://kauwa-udd.vercel.app. Free game, guest login, maintenance mode.

Product id: `kauwa-udd` (`NEXTJEDI_PRODUCT`). Next.js 16 App Router, React 19, TypeScript, Tailwind 4,
pnpm. Built on the NextJedi Studio Platform (`nextjedi-world/platform`). The repo is **public**, so CI is inlined
(see CI below). Originally generated by v0 (the v0 project link must stay intact; v0 pushes to `main`).

## Commands (use `make`, they wrap pnpm)

| Task                       | Command                                                                         |
| -------------------------- | ------------------------------------------------------------------------------- |
| Install deps and git hooks | `make setup` (`pnpm install --frozen-lockfile`)                                 |
| Run locally (:3000)        | `make dev`                                                                      |
| Everything CI checks       | `make verify` = lint + format check + typecheck + test + build                  |
| Lint / format / typecheck  | `make lint`, `make format`, `make typecheck`                                    |
| Unit tests (Vitest)        | `make test`, `pnpm test:coverage` for coverage                                  |
| Local DynamoDB             | `pnpm db:local` (DynamoDB Local on :8000), then `pnpm db:setup`, `pnpm db:seed` |
| Browser e2e                | none yet; `make e2e` runs the unit tests                                        |

`make verify` is what CI and the Stop hook run. Do not finish a task while it fails.

## Layout

- `app/` routes. `app/api/rooms/**` room lifecycle (create, join, ready, start, click, settings, leave,
  restart), `app/api/leaderboard`, `app/api/ably/token`, `app/api/auth/[...nextauth]`.
- `lib/game/engine.ts` pure game logic (shuffle, round objects, eliminations, standings, winner).
  `lib/types.ts` types and `scoreRound` scoring. `lib/game-data.ts` object catalogue, languages, room codes.
- `lib/db/` DynamoDB single-table access. `keys.ts` is the only place key shapes are built; see `docs/SCHEMA.md`.
- `lib/realtime/` Ably client and channels. `lib/log.ts` structured JSON logger.
- `workflows/game.ts` Vercel Workflow that drives rounds. `auth.ts` Auth.js (guest credentials).
- `scripts/` DynamoDB local setup, table creation, seed. `docs/` API, schema, QA report, submission copy.
- `instrumentation.ts` optional Sentry init, only active when `SENTRY_DSN` is set.

## Rules

- Do not change game behaviour while doing hygiene work. Put logic in `lib/` and unit-test it next to the file.
- Server code logs with `log` from `lib/log.ts` (JSON lines), not `console.*`.
- Secrets never go in git. Local values live in `.env.local` (ignored); names are in `.env.example`.
  Production reaches DynamoDB through Vercel OIDC (`AWS_ROLE_ARN`), there are no stored AWS keys.
- Do not touch: the DynamoDB tables' data, Vercel production env vars, the v0 project link.
- Every change maps to a Linear issue (team NEX, project Kauwa Udd). PR body has `Fixes NEX-123`.
  Conventional commits; the commit-msg hook and the commitlint workflow enforce them.
- This Next.js version may differ from your training data: read `node_modules/next/dist/docs/` first.

## CI and release

- `.github/workflows/ci.yml` runs `make setup` then `make verify` on PRs and pushes to `main`.
  It mirrors `nextjedi-world/platform` `ci-web.yml`, inlined because a public repo cannot call a private
  reusable workflow. `commitlint.yml` checks the PR title and the `Fixes NEX-` reference.
- Vercel Git integration deploys `main` to production and every PR to a preview.
- Renovate extends `github>nextjedi-world/platform//renovate/default`. `release-please-config.json` is
  present; a release workflow is not wired yet.
- Claude review/mention workflows are not added: they live in the private platform repo.

## Known gaps

- No Playwright e2e. No PostHog, privacy policy, feedback or account deletion (decision: NEX-1187).
- ESLint rules that flagged existing code were set to warnings so CI stays green; fix them gradually.
